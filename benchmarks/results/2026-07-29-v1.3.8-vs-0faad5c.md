# v1.3.8 versus `0faad5c`

This same-machine baseline compares the published `v1.3.8` source
(`95c4548d57b61fb7a071f1cbc3c35eae0ccabe21`) with candidate commit
`0faad5c00527f23af3749c6ba46c49b325cf41f8`. Both were exported with
`git archive`, built independently with Rust/Cargo 1.95.0 and cargo-dist 0.32.0,
and used the `dist` profile with all features.

Environment:

- Linux 7.1.4-arch1-1 x86_64, glibc 2.43;
- AMD Ryzen AI Max+ 395, 32 logical CPUs;
- 100 fixed-seed interleaved warm samples per command, five warmups;
- 30 fixed-seed interleaved cold-start samples per binary;
- isolated empty `XDG_CONFIG_HOME`, `LC_ALL=C`, and `NO_COLOR=1`;
- 10-second per-process deadline;
- no process termination, synthetic Docker/network fixture, or system-wide cache
  purge; `list` observed the same live host state for both builds.

Every correctness probe produced `kickoutchi 1.3.8`, matching human-output
lengths, valid JSON with matching lengths, and exit status zero. All 660 measured
processes also exited zero without a timeout.
